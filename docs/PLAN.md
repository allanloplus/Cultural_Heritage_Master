# 文資達人訪查網站 — 規劃書

- 規劃：Allan Lo，2026 年 11 月
- Repo：`allanloplus/Cultural_Heritage_Master`（GitHub Pages）
- 姊妹站：文資知識網站「Allan Lo 和你逛文化」 https://cultural.123hi.org/（`Cultural_Heritage`）、https://cultural2.123hi.org/（`Cultural_Heritage2`）

## 1. 目標

知識網站的內容來自文化部文化資產局開放資料與維基百科，說的是「這處文資是什麼」。本站記錄「這處文資**現在**怎麼樣、值不值得去」：

1. 文資達人實地訪查後，更新**參訪日期、文資現況、開放情形、參訪心得、當天心情、實地照片、推薦指數**，以及**附近推薦**（美食、住宿、交通、其他景點）。
2. 不只 Allan Lo 更新，開放更多達人參與；達人必須**申請、審查、核准**後才能發表。
3. 統計每位達人的**預計到訪與實際到訪**。
4. **查核資訊**：各縣市知識網站收錄多少文資、多少已有訪查紀錄、覆蓋率、近一年更新、需回訪、預計到訪。
5. 兩站**雙向連結**：知識網站每處文資的詳情都有「達人實地訪查・現況與推薦」按鈕；本站每處文資都連回知識頁。

## 2. 使用情境：2026/11/7–11/10 金門行

1. 出發前：到「查核資訊 › 金門縣」，按 **規劃訪查行程**，篩選「尚未訪查」或依鄉鎮（金城、金湖、金沙、金寧、烈嶼）勾選這趟要看的文資，填行程名稱「2026 金門行」與 11/7–11/10，一次登記成預計到訪。
2. 「我的訪查」會出現這趟行程的清單、完成進度，以及「在 Google 地圖開啟未完成景點的路線」。
3. 在現場或當晚：清單上按 **填寫紀錄**，用手機填現況、心得、心情、推薦指數，拍照直接上傳（瀏覽器先縮圖、移除 GPS），再加上附近推薦（例如廣東粥、貢糖店、民宿、公車路線）。
4. 送出後，該處文資的預計到訪自動標成「已完成」；達人統計的「預計／實際」與查核資訊的覆蓋率同步更新。
5. 發現知識網站資料和現場不符（例如已整修、開放時間改了），填在「資料勘誤」，回頭修正知識網站。

## 3. 角色與權限

| 角色 | 取得方式 | 可以做什麼 |
|---|---|---|
| 訪客 | 不需登入 | 閱讀公開紀錄、查核資訊、達人統計 |
| 會員 member | email 登入（免密碼連結） | 申請成為達人、編輯個人資料 |
| 文資達人 expert | 申請經審查核准 | 新增／修改自己的訪查紀錄、上傳照片、登記預計到訪與行程 |
| 審查者 reviewer | 管理者指派 | 審核達人申請與訪查紀錄、退回或下架、查看稽核紀錄與勘誤 |
| 管理者 admin | Allan Lo | 審查者權限＋調整角色與「免審」標記 |

- **免審（trusted）**：管理者可對信任的達人（例如 Allan Lo）開啟，送出即公開；其他達人送出的紀錄先進「待審」，審查者核准後公開。修改已公開的紀錄會重新送審。
- 權限在資料庫層用 Row Level Security 強制，不靠前端隱藏按鈕（見 `supabase/schema.sql`）。

## 4. 流程

```
會員註冊 ─► 填寫達人申請（署名、真實姓名*、聯絡*、擅長縣市、資歷、作品連結、同意規範）
          ─► 審查者核准／不通過（必填原因）─► 核准後角色自動升為 expert           * 僅審查者可見

達人 ─► 規劃行程／登記預計到訪 ─► 實地訪查 ─► 填寫紀錄＋照片＋附近推薦
     ─► trusted？ 是：直接公開 ／ 否：待審 ─► 審查者核准公開 或 退回（必填意見）─► 作者修改再送審
```

所有核准、退回、下架、角色變更都寫入 `audit_log`（誰、何時、對象、意見）。

## 5. 訪查紀錄欄位

| 欄位 | 說明 |
|---|---|
| 縣市、文資 | 從知識網站的文資清單選擇（`county_slug`＋`site_id`，即知識網站的資料夾與景點 id） |
| 實際參訪日期 | 不能是未來日期 |
| 文資現況 | 良好／尚可／待修繕／修復施工中／閉館或封閉／已消失或拆除 |
| 開放情形 | 正常開放／限時或預約／僅能看外觀／未開放 |
| 推薦實際參訪指數 | 1–5 星（必填）；另有五個分項：歷史價值、保存狀況、解說資訊、參觀友善、交通便利 |
| 當天心情 | 驚喜／感動／愉快／普通／可惜 |
| 參訪心得 | 30–5000 字 |
| 參訪建議、費用、停留時間、人潮、無障礙 | 選填 |
| 附近推薦 | 最多 10 筆：類型（美食、住宿、交通、景點、其他）、名稱、說明、連結 |
| 實地照片 | 最多 6 張，每張可寫說明、選授權（預設 CC BY-SA 4.0） |
| 資料勘誤 | 回報知識網站或官方資料與現場不符之處 |
| 對應預計到訪 | 連結行程中的預計到訪，送出後自動完成 |

## 6. 統計

- **查核資訊**（每縣市與全臺）：文資數、已訪查處數、覆蓋率、近一年更新、需回訪（最近一次訪查超過 2 年，可在 `config.js` 調整）、預計到訪、紀錄筆數；另有依文資類別的覆蓋率；可下載 CSV。
- **縣市頁**：每處文資的最近訪查日、最新現況、平均推薦、紀錄數；可篩選「尚未訪查／已訪查／需回訪／預計到訪」，方便挑下一趟要去的地方。
- **達人統計**：公開紀錄數、訪查文資處數、涵蓋縣市、預計到訪、已完成、逾期未訪、達成率、最近訪查；個人頁有「每月預計與實際到訪」長條圖與行程清單。
- 統計只計「已公開」紀錄；資料庫端由 `v_site_stats`、`v_expert_stats` 兩個檢視表提供。

## 7. 架構

```
GitHub Pages（靜態網站，本 repo）
  index.html + assets/js/{config,store,app}.js
  data/heritage-index.json  ← tools/build_index.py 從兩個知識網站 repo 產生（3,032 處文資）
        │ supabase-js（anon key，公開）
        ▼
Supabase
  Auth：email 免密碼登入
  Postgres：profiles / expert_applications / visits / visit_photos / visit_plans / audit_log ＋ RLS
  Storage：visit-photos bucket（<user_id>/<visit_id>/<n>.jpg，只能寫自己的資料夾）
```

- 選 Supabase 的理由：GitHub Pages 只能放靜態檔，多人投稿、登入、審查、照片上傳需要後端。Supabase 有免費方案，Auth、資料庫權限（RLS）、檔案儲存一次到位，不需要自己維護伺服器。
- **示範模式**：`config.js` 沒填 Supabase 時，網站以瀏覽器 localStorage 運作，可切換「Allan Lo（管理者）／示範達人／示範會員／訪客」試用全部流程。示範資料都標「示範」。
- 知識網站改版、文資增減時，重新執行 `python3 tools/build_index.py` 更新清單。景點 id 改名會讓舊紀錄對不上，知識網站應避免改 id。

## 8. 資安與個資（ISMS／PIMS 考量）

| 項目 | 作法 |
|---|---|
| 存取控制 | 角色分級＋資料庫 RLS；會員不能自行提升角色（觸發器擋下，已用測試驗證）；審查者才看得到申請者真實姓名與聯絡方式 |
| 最小蒐集 | 只蒐集 email、公開署名；真實姓名、聯絡方式僅供審查，選填 |
| 照片個資 | 前端重新繪製輸出 JPEG，移除 EXIF（含 GPS、裝置）；投稿規範要求避免可辨識路人、車牌、私宅內部 |
| 稽核軌跡 | 核准、退回、下架、刪除、角色變更寫入 `audit_log`，只有審查者可讀 |
| 金鑰管理 | 網頁只放 anon key；service_role key 絕不放前端或 repo |
| 內容治理 | 投稿規範＋同意聲明；退回必填意見；已公開紀錄只能由管理者刪除或下架 |
| 已知限制 | 照片 bucket 為公開讀取（路徑含隨機 UUID，不可列舉），待審紀錄的照片若網址外流仍可被開啟；若需更嚴格，可改私有 bucket＋signed URL |
| 當事人權利 | 作者可修改、刪除未公開紀錄；帳號與已公開內容刪除由管理者處理（關於頁有說明） |
| 備份 | Supabase 每日備份（付費方案）或定期以 `pg_dump`／CSV 匯出 |

## 9. 上線步驟

1. 建立 Supabase 專案 → SQL Editor 執行 `supabase/schema.sql`。
2. Authentication → URL Configuration：Site URL 與 Redirect URLs 加入本站網址。
3. 把 Project URL、anon public key 填入 `assets/js/config.js`。
4. 用 Allan 的 email 在網站登入一次，SQL Editor 執行：
   `update public.profiles set role='admin', trusted=true where id=(select id from auth.users where email='…');`
5. GitHub Pages：Settings → Pages → Deploy from branch `main` / root。要用自訂網域（例如 `visit.123hi.org`）就加 `CNAME`，並把知識網站 `assets/js/city/app.js` 的 `VISIT_BASE` 改成新網址。
6. 邀請第一批達人申請、審核。
